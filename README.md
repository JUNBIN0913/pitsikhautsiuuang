# 僻字考究網 — 使用說明

## 檔案結構
```
index.html   前台＋後臺合併為單一檔案
data.json    示範資料 / Firebase 未設定時的離線資料來源
fonts/       五套字型檔
```
三者請保持在同一層目錄，整組上傳到您的網站空間（GitHub Pages、Firebase Hosting、或任何靜態網站主機皆可）。

**如何進入後臺**：網站最上方有一條窄版導覽列，右側「後臺」連結可切換到登入畫面（同一頁面內切換，不會跳轉網址）；也可以直接在網址後面加上 `#admin` 分享／加入書籤。登入畫面／後臺畫面都受 Firebase 帳號密碼保護，一般訪客點進去沒有帳密一樣看不到任何管理功能。

## 一、Firebase 串接（即時同步，免手動上傳）

### 1. 建立 Firebase 專案
前往 https://console.firebase.google.com → 新增專案。

### 2. 啟用兩項服務
- **Firestore Database**：主控台 → Build → Firestore Database → 建立資料庫。
- **Authentication**：主控台 → Build → Authentication → Sign-in method → 啟用「電子郵件/密碼」，並在 Users 分頁手動新增您自己的管理者帳號（Email＋密碼），這組帳號就是您登入後臺用的帳號。

> 不需要啟用 **Storage**。Firebase Storage 需要升級到 Blaze（用量計費）方案才能使用，因此圖片（參考文獻圖片、尚未造字的字形圖片）改為在瀏覽器端自動壓縮後，直接以 base64 格式存進 Firestore 文件裡，完全在免費方案（Spark）額度內即可運作。

### 3. 取得設定物件並填入
主控台 → 專案設定（齒輪圖示）→ 一般 → 往下捲到「您的應用程式」→ 新增網頁應用程式 → 複製出現的設定物件，貼到 **index.html 裡的 `FIREBASE_CONFIG`**（檔案中段的 script 區塊，前後台共用同一份設定，只需填一次）：
```js
const FIREBASE_CONFIG = {
  apiKey: "...", authDomain: "...", projectId: "...",
  storageBucket: "...", messagingSenderId: "...", appId: "..."
};
```
填入後儲存即生效。**在填入之前**，網站會自動退回「本機示範模式」：前台讀 `data.json`；後臺存瀏覽器 localStorage、免登入，方便您先熟悉介面。

### 4. 設定安全規則
**Firestore 規則**：
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /characters/{docId} {
      allow read: if true;
      allow write: if request.auth != null;
    }
    match /reports/{docId} {
      allow create: if true;
      allow read, update, delete: if request.auth != null;
    }
  }
}
```
**Storage 規則**：不需要設定（本專案未使用 Firebase Storage）。

> **圖片大小提醒**：Firestore 單筆文件上限為 1MB。上傳圖片時網站會自動壓縮（標題字形圖片長邊約壓到 900px、參考文獻圖片約 700px，JPEG 品質約 80%），一般使用綽綽有餘；但若單一字條放了很多張參考文獻圖片，儲存前會跳出提醒。若某個字條需要收錄大量或高解析度圖片，建議把圖片放到您自己的圖床或雲端空間，在「說明文字」欄位改附上連結即可。

### 5. 串接完成後的行為
- 後臺新增／編輯／刪除字條，直接寫入 Firestore；前台**重新整理頁面即可看到最新內容**，不需要匯出/匯入 data.json，也不需要手動上傳檔案到主機（跟您「國音彙考」的做法一致）。
- 「回報信箱」即時顯示前台送出的問題回報，可逐筆刪除或一鍵清空。
- 「匯出 data.json」按鈕仍保留，純粹作為**備份**用途，並非日常更新資料的必要步驟。

14. 參考文獻圖片點擊後會以放大檢視開啟，可用滑鼠滾輪縮放、拖曳移動、雙擊還原，只能按右上角的 ✕ 關閉（不會因為點到圖片周圍就意外關閉）。

## 三、關於「套用字型後仍無法顯示」的根本原因（重要）

我實際用工具檢查了您提供的五套字型檔的內部編碼方式，發現關鍵問題：

- **TW-Kai、TW-Kai-ExtB**：使用「標準 Unicode 碼位」。TW-Kai-ExtB 的罕用字集中在 Unicode 擴展區 B～F（U+20000–U+2FFFF），只要文字是這個範圍內的標準編碼，選對字型就會正常顯示。
- **TW-Kai-Plus**：這套「增補字」幾乎全部（24,978字）是用 **Plane 15 私用區（Private Use Area，U+F0000–U+FFFFD）** 編碼，NomNaTong 也有一部分（6,537字）用同樣方式。

這代表 TW-Kai-Plus 裡的罕用字**沒有對應的標準 Unicode 碼位**，是教育部／全字庫這類專案常見的做法：沒有標準碼位的字，各自用私用區碼位搭配專屬字型來顯示。**這也是為什麼即使選對了「TW-Kai-Plus」字型，文字卻還是顯示方框**——不是我們網站程式的問題，而是您輸入／貼上的那個文字，其編碼碼位跟這套字型內部登記的碼位對不上（例如是用輸入法直接打出來的相似字、或從別的網站用別的字型複製過來的字，两者長得一樣但底層編碼不同）。

**解決辦法**：
1. 要使用 TW-Kai-Plus 或 NomNaTong 裡的罕用字時，請直接從**教育部全字庫**（https://www.cns11643.gov.tw/）或其他官方全字庫查詢頁面複製該字，才能確保碼位與字型內部登記的一致。
2. 如果實在找不到正確碼位、或這個字根本沒有被任何字型收錄，直接使用後臺的「此字尚未造字／無對應 Unicode，暫以圖片表示」功能即可——這個功能就是為了處理這種情況而設計的。
3. 如果您把某個顯示不出來的字（或它在全字庫上的碼位）告訴我，我可以直接用工具檢查這幾套字型裡到底有沒有收錄、碼位是什麼，幫您確認問題出在哪。

### 已解決案例：𲎱（U+323B1）
您提供的「𲎱」字經過檢查後發現：TW-Kai、TW-Kai-Plus、TW-Kai-ExtB、NomNaTong 這四套字型檔**都沒有**收錄這個字（碼位落在 Unicode 第三平面，屬於 2022 年才新增的 CJK 擴展區 H／I，是非常新的字）。

但您原本上傳的「文津明朝」字型檔（`WenJinMinchoW-TTF.ttc`）其實內建三個字面（Plane 0／Plane 2／Plane 3），我們先前只抽取了 Plane 0（一般漢字）。重新檢查後發現 **Plane 3 字面剛好收錄了這個字**，所以我已經把 Plane 3 也抽取出來（`fonts/WenJinMincho-Plane3.woff2`），並在後臺的字型選單新增一個選項「**文津明朝 Plane3（Unicode 第三平面罕見字）**」。

請到後臺把「𲎱」這筆字條的顯示字型改選成這個新選項，應該就能正常顯示了。如果您有其他字也顯示不出來，一樣可以把字或碼位告訴我，我可以檢查是否落在 Plane 2（也已備妥、如需要可以另外加入）或其他範圍。

## 字型技術提醒

**文津明朝字型**：原始檔 `.ttc` 格式在 Chrome／Firefox／Edge 的 `@font-face` 支援度很差，已抽取其中三個字面並各自轉換為獨立字型檔：
- `WenJinMincho`（Plane 0，一般漢字）
- `WenJinMincho-Plane2`（涵蓋 Unicode 擴展區 B～F，U+20000–U+2FFFF）
- `WenJinMincho-Plane3`（涵蓋 Unicode 擴展區 G 以後，U+30000 以上）

後臺的字型選單、釋義編輯器的逐字套字型選單都已經加入這兩個新選項，可依文字實際落在哪個範圍選用對應字型。

> **關於「𲎱」等看起來已經有標準編碼、卻還是顯示方框的字**：我用工具實際檢查過，「𲎱」（U+323B1）落在 Unicode 擴展區 G，屬於 `WenJinMincho-Plane3` 這個字面才有收錄的範圍——先前網站只掛載了 Plane 0，難怪選了字型也顯示不出來。現在已經補上 Plane 2／Plane 3 兩個字面，這類字改選「文津明朝 Plane3」應該就能正常顯示了。如果之後還遇到選對字型仍顯示方框的情況，把那個字或它的 Unicode 碼位告訴我，我可以直接用工具檢查五套字型（含這兩個新字面）裡到底有沒有收錄。

**檔案大小**：五套字型原始檔總計約 150MB（TW-Kai-Ext-B 單檔 46MB），這是完整 CJK 字型難以避免的量級，網站可正常運作，但行動網路下初次載入對應字型可能較慢。之後可視資料庫實際用到的字做「子集化」大幅縮小體積，需要時我可以協助處理。

## 資料格式（characters 文件結構）
```json
{
  "char": "齉",
  "charImage": "",
  "zhuyin": ["ㄋㄤˋ"],
  "pinyin": ["nàng"],
  "radical": "鼻",
  "totalStrokes": 36,
  "ids": "⿰鼻齉省",
  "definition": "<p>HTML 格式的釋義內容，可能包含 <font face=\"WenJinMincho\">指定字型</font> 的片段…</p>",
  "references": [{ "img": "URL 或 base64", "caption": "文獻出處說明" }],
  "font": "tw-kai"
}
```
`charImage` 有值時代表這是「尚未造字」的圖片字，此時 `char` 與 `font` 為空字串。

`data.json` 內含 5 筆示範資料，供您在正式串接 Firebase 前先熟悉介面。串接完成後，建議直接在後臺登入並逐筆新增正式資料；若想把既有資料一次性匯入 Firestore，跟我說一聲，我可以幫您寫一支匯入小工具。
